# Production Readiness: Final Pipeline Audit & Known Issues

All five blockers below were resolved on branch `release/v1.0` (cut from
`feature/agentic-hardening`). Three additional voice-brief items
(paid-key scaling, loss-driven auto-revamp, research/grounding) were
also addressed. See the launch plan in
`.claude/plans/c-users-tanish-jagtap-desktop-no-code-1-swirling-bear.md`
for the full implementation notes.

## 1. Massive Dataset Processing (The "Mahabharata" Problem) — RESOLVED
**Fix:** `DataRestructurerAgent` now processes chunks in sliding
windows of `MAX_INFLIGHT_CHUNKS` (default 8) via `asyncio.gather`.
Per-window throughput scales with the multi-key rotation pool
configured in Settings. A short "running context" is built between
windows from representative pair examples so the LLM stays on-theme
across the whole document (e.g. Krishna ↔ Arjuna stays Krishna ↔
Arjuna across 100+ chunks). Hash-based dedup at the end drops the
duplicate rows that come from the chunker's 400-char overlap.

Touched: `backend/app/agents/data_restructurer.py`,
`backend/app/tools/alchemy.py` (running_context parameter).

## 2. Dynamic VRAM & Hyperparameter Auto-Tuning — RESOLVED
**Fix:** Programmatic VRAM math in `backend/app/utils/hardware.py`
(`compute_vram_budget`, `clamp_strategy_to_vram`). After the LLM
chooses a strategy in `TrainingStrategyAgent`, the clamp halves
`batch_size` / `max_seq_len` until the run fits in ≤85% of detected
VRAM. The clamp diff is surfaced in chat. New tool
`hardware.vram_budget` exposes the math to the LLM for explicit
sanity checks.

Touched: `backend/app/utils/hardware.py`,
`backend/app/tools/hardware.py`, `backend/app/agents/strategy.py`.

## 3. Hugging Face README / Model Card Generation — RESOLVED
**Fix:** `hf_service.start_push` now writes a `README.md` into the
local model directory before `upload_folder` so the Hub repo lands
with a real model card: base model link, dataset name / row count /
format, method, epochs, effective batch, learning rate, final loss,
training duration, inference snippet, license. Best-effort — any
metadata gap falls back to a placeholder rather than skipping the
card.

Touched: `backend/app/services/hf_service.py` (`_build_model_card`,
`_write_model_card`).

## 4. Robust Pipeline Interruptions ("Stop this process") — RESOLVED
**Fix:** Hard-wired stop intent in the AgenticLoop. When a user
message starts with `stop|abort|cancel|halt|kill` (regex match) AND
any job is active for that session, `job_service.stop_all_session_jobs`
is called synchronously *before* the LLM ever sees the message. A
system directive is appended so the next assistant turn acknowledges
the stop rather than restarting work. Trainer-side: stop checks now
run in `on_train_begin`, `on_epoch_begin`, `on_step_begin`, `on_log`,
and `on_step_end` instead of only at step boundaries — stop latency
drops from "next step" (can be many seconds) to ~1 second.

Touched: `backend/app/agents/loop.py`,
`backend/app/services/job_service.py`,
`backend/app/training/trainer.py`.

## 5. In-flight Data Formatting & Conversion Limits — RESOLVED
**Fix:** New `backend/app/services/jsonl_validator.py` defines a
pydantic schema per `_FORMAT_OPTIONS` value. After restructuring,
rows are validated; malformed rows are dropped or lightly repaired
(bare string `messages` -> `[{role:user, content:...}]`,
`prompt`/`completion` -> chat turns, `question`/`answer` ->
`instruction`/`output`). Surfaced as a "kept N / dropped M /
repaired K" message in chat. The trainer never sees a row that
doesn't match its expected shape.

Touched: `backend/app/services/jsonl_validator.py`,
`backend/app/agents/data_restructurer.py`.

## 6. Paid-Key Scaling (voice brief) — RESOLVED
**Fix:** Multi-key rotation was already wired in `providers.py:75-105`
via `<PROVIDER>_API_KEYS` env vars. Now also exposed through the UI:
Settings -> "show multiple-key rotation (paid-tier scaling)" reveals
a textarea where the user can paste multiple keys. Backend encrypts +
persists them and mirrors to env so the existing rotation kicks in on
the next call. Each key gets its own RPM/TPM bucket; N keys ~ N x
effective throughput. Power users can also raise the static limits in
`data/provider_limits.json`.

Touched: `backend/app/api/schemas/settings.py`,
`backend/app/api/routes/settings.py`,
`frontend/src/app/settings/page.tsx`,
`frontend/src/lib/types.ts`.

## 7. Loss-Driven Auto-Revamp (voice brief) — RESOLVED
**Fix:** Trainer's `_StreamCallback` now detects non-finite loss
(NaN / Inf) and calls a new `on_anomaly` callback that emits a
`TrainingAnomalyDetected` event with `reason="loss_nan_or_inf"`.
Existing `RecoveryAgent` (already wired) picks this up and proposes
a conservative recovery plan via `recovery.propose_plan`: cut LR by
4x, force fp16. Existing policy auto-approves up to `max_recoveries`
attempts then escalates to the user.

Touched: `backend/app/training/trainer.py`,
`backend/app/services/job_service.py`.

## 8. Research-Augmented Agents + Gemini Grounding (voice brief) — RESOLVED
**Fix:** `web_search` and `model.search_hf` added to
`TrainingStrategyAgent.allowed_tools`; `web_search` added to
`DatasetIntakeAgent.allowed_tools`. New top-of-chain backend
`_gemini_grounding` in `web.py` that uses the native `google-genai`
SDK (or legacy `google-generativeai`) with `tools=[google_search]` —
returns citations directly from Gemini when the user is on a Gemini
paid key. Silent no-op (chain falls through to DDG -> Google ->
SearXNG -> Wikipedia) when the SDK is missing, the user is on a
different provider, or the key lacks grounding permission. Added
in-process TTL cache (10 min) so multi-agent workflows don't re-hit
the chain for identical queries.

Touched: `backend/app/agents/strategy.py`,
`backend/app/agents/intake.py`, `backend/app/tools/web.py`.
