# Production Readiness: Final Pipeline Audit & Known Issues

Before pushing FineTune Studio to production, an audit of the pipeline functionality against the requested edge cases reveals the following remaining structural problems. These issues need to be addressed to ensure industrial-grade stability.

## 1. Massive Dataset Processing (The "Mahabharata" Problem)
**Issue:** If a user uploads an entire raw book (e.g., the Mahabharata) and requests an extraction of a specific conversation (e.g., between Krishna and Arjuna), the system will struggle heavily.
**Why:** 
* The `DataRestructurerAgent` processes raw documents by chunking the text and running a synchronous LLM call on *every single chunk* to synthesize dataset pairs.
* For a book the size of the Mahabharata, this will trigger hundreds or thousands of synchronous API calls, resulting in severe rate-limiting (429 errors), quota exhaustion, and extremely long processing times.
* Furthermore, extracting a hyper-specific dynamic (only Krishna and Arjuna) requires deep context tracking across chunks, which the stateless chunk-by-chunk extraction prompt (`alchemy.build_restructure_prompt`) does not natively enforce.

## 2. Dynamic VRAM & Hyperparameter Auto-Tuning
**Issue:** The system does not mathematically guarantee the chosen hyperparameters will fit on the user's GPU.
**Why:**
* While we implemented a "CPU Safe-Mode" guard, the actual hyperparameter selection for GPU training (batch size, sequence length, gradient accumulation) is currently left to the LLM's reasoning in `PipelineBuilderAgent` / `TrainingStrategyAgent`.
* The LLM guesses reasonable defaults, but it does not perform strict VRAM limit calculations. A generic LLM guess could easily result in a batch size or `max_seq_len` that triggers an Out-Of-Memory (CUDA OOM) crash during training. True production pipelines require programmatic VRAM sizing formulas prior to launch.

## 3. Hugging Face README / Model Card Generation
**Issue:** Uploads to the Hugging Face Hub lack documentation.
**Why:**
* The `export.push_hf` tool (via `hf_service.start_push`) successfully uploads the output folder to the Hugging Face Hub using the `huggingface_hub` library.
* However, it only uploads the adapter weights and tokenizer files. It does **not** dynamically generate or upload a `README.md` (Model Card) detailing the base model, training dataset, epochs, loss metrics, or chat templates.

## 4. Robust Pipeline Interruptions ("Stop this process")
**Issue:** Stopping a running job mid-flight relies entirely on LLM reasoning and thread signaling, which can be flaky.
**Why:**
* When a user types "stop this process", the `AgenticLoop` safely cancels its internal LLM stream and restarts.
* However, actual training runs in a background thread and the tool wrapper `run_training` is marked `cancel_safe=False` (it is shielded from Python's asyncio cancellation). 
* To actually kill the training, the LLM must successfully reason that it needs to call the explicit `job.stop` tool. If the LLM misunderstands or fails to call it, the heavy training thread keeps consuming resources in the background.

## 5. In-flight Data Formatting & Conversion Limits
**Issue:** Custom format conversion during conversation works for standard schemas but fails for complex contextual filtering.
**Why:**
* If a user says "convert this dataset into a specific format," the system works well for standard targets (instruction, chat, qa, classification) because these are natively supported in `_FORMAT_OPTIONS`.
* If the user requests a highly non-standard format or a heavily filtered conversion (e.g., "only extract rows with medical terms"), the pipeline relies entirely on the LLM's prompt adherence during the restructuring phase. For large datasets, the AI agents may lose context or hallucinate formats across different chunks, leading to malformed JSONL files that will break the downstream training node.

---
**Maintainer Summary:**
To declare this production-ready, we must:
1. Implement async/batch processing for the `DataRestructurerAgent` to prevent rate-limits on massive files.
2. Add a programmatic VRAM calculator to clamp the LLM's hyperparameter choices before training.
3. Inject a `README.md` generator into `export.push_hf`.
4. Hard-wire a direct "Abort Job" interrupt sequence that bypasses LLM tool-calling for guaranteed stops.
